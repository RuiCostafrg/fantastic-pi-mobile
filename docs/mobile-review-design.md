# A calmer, mobile IDE-style review

Research and implementation notes, 2026-10-16, version 0.6.0.

## Verified primary sources

- **VS Code Source Control overview**: changed files belong in the source-control view; users review differences before staging/committing. Working changes and staged changes are distinct concepts. [Official documentation](https://code.visualstudio.com/docs/sourcecontrol/overview), retrieved successfully.
- **GitHub pull-request review**: the Files changed view supports unified and split diffs, file filtering/navigation, and source versus rich views. [Official documentation](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/reviewing-proposed-changes-in-a-pull-request), retrieved successfully after its canonical redirect.
- **Android accessibility**: interactive elements should have at least 48 × 48dp touch targets, suitable contrast, and meaningful descriptions. [Official guidance](https://developer.android.com/guide/topics/ui/accessibility/apps), retrieved successfully.
- **Android font scaling**: Android 14 supports nonlinear scaling up to 200%; developers should test maximum font settings rather than assume labels fit. [Official documentation](https://developer.android.com/about/versions/14/features#non-linear-font-scaling), retrieved successfully.
- **Catppuccin**: the official Mocha palette provides Base `#1e1e2e`, Mantle `#181825`, Surface0 `#313244`, Text `#cdd6f4`, Subtext0 `#a6adc8`, Lavender `#b4befe`, Green `#a6e3a1`, and Red `#f38ba8`. [Official palette/project](https://github.com/catppuccin/catppuccin), retrieved successfully. Pi Pocket uses an inspired palette and its own UI code, not a copied editor theme implementation.

A guessed VS Code review-changes URL and an older GitHub commit-review URL returned 404 and were not used as evidence. No browser/background research agent was available; sources were fetched directly over HTTPS and inspected locally. This is a native Android layout informed by these patterns, not an embedded VS Code instance or a claim that desktop split panes are suitable on a phone.

## Product choices

1. **Contextual navigation.** Remove the always-present Δ glyph from the chat toolbar. Show a clearly labeled “Review N changed files” action only for that chat's actual working or committed file changes. Deduplicate files appearing in both sections. Also retain access for a running repository action or an uncertain persisted request—even when files are clean—so users can inspect/stop a test or resolve its exact saved ID. Hide Changes in the chat menu under the same rule. An ordinary answer does not imply a code change.
2. **Cheap, read-only discovery.** The bridge's `GET …/changes?summary=1` reads Git status and committed filenames without file-content hashes, creating a worktree, or fetching a remote. The selected visible chat checks periodically; switching chats/returning to the screen invalidates old state. Late responses cannot supply another chat's indicator. On connection failure, do not claim there are zero files; hide the unavailable navigation entry except for a locally pending operation. Older protocol-v4 bridges returning full snapshots remain usable.
3. **Filename-first file list.** Plain-language Added/Modified/Deleted/Conflict labels replace porcelain codes. The whole filename wraps; the folder is separate. Checkboxes select whole working files, never hunks. Committed changes remain visible until integration. Archived reviews omit mutation controls rather than filling the screen with disabled buttons.
4. **One-column, full-screen diffs.** A phone gets a unified code view rather than two narrow desktop columns. Before/after line-number gutters, `+`/`−` signs, tinted full-line backgrounds and hunk separators make changes legible without relying on color alone. Preserve code spacing and do not soft-wrap logical code lines; horizontal scrolling is explicitly labeled. Long filenames wrap in the title. Raw patch and Copy patch retain exact original data; presentation parsing never changes the commit operation.
5. **Progressive disclosure.** Long worktree paths, generated branch IDs and commit hashes move behind Branch & folder details. Files are primary; Checks and local integration are separate scrollable cards. Only the selected-file commit action is pinned. Existing confirmation, permissions, revision checks, test-evidence wording and no-push behavior remain unchanged.
6. **Calm native theme.** Mocha-inspired low-glare surfaces, a restrained lavender accent and readable muted text replace the colder heavy toolbar. Toolbar controls use vector strokes and meaningful descriptions instead of font glyphs. Text buttons use wrap-content heights with a 48dp minimum; padding is explicit, including dialog fields. Main chat's finish action is quieter, and Stop is hidden when no chat request is active.

## Reproduction and validation

- Before the fix, an ADB UI assertion failed because an empty chat exposed Review changes.
- A native regression test was run against installed 0.5.0: its actual merge button had a fixed 48dp height rather than wrap-content. This failed before installing the new build, not just against a hand-made mock.
- Geometry tests exercise real file-row widgets with long paths at 320dp / font scale 2.0, text-height/ellipsis checks, and 48dp icon touch minima. A native full-screen viewer test checks that long code stays on one logical line, scrolls horizontally, and Raw patch preserves exact data.
- Parser tests cover hunk line arithmetic, source lines beginning with extra `+`/`-`, new files, binary/link messages, empty files and end-of-file annotations. Backend tests cover non-creating/chat-scoped summaries, unique file counts before/after commits and integration, large files without content reads, authentication, and active-operation availability.
- Real phone/provider workflow in a disposable repository: an ordinary answer kept Changes hidden; two Kotlin edits exposed Review 2 changed files; the long filename and before/after red/green diff were inspected; native tests passed; selecting and committing files separately moved them from Working files to Already committed without hiding Changes; a confirmed local merge produced All caught up and removed the chat action. No test merge touched the actual project default branch.

History, pairing, stable request/operation IDs, unfinished worktrees and the original local bridge are preserved. This is still read-only diff review, not code editing, hunk staging, conflict resolution, remote pushing or a full desktop IDE.
